# Published snapshot tables

The predictions route `/crosscheck/predictions` reads only two standalone publication tables through `CROSSCHECK_PUBLISHED_DATABASE_URL`. It does not import the live research pool, fall back to `DATABASE_URL`, query live ledger tables, ingest, lock, or score. The inherited main layout still uses its existing deals-metadata query; that is unchanged. No Supabase SQL has been applied by this work.

Owner setup:

1. Review and run `earnings/sql/published_snapshots.sql` in the intended Supabase database as administrator. It creates real copy tables, not views or foreign keys to the ledger. `dealtrace_web` receives SELECT only, RLS is enabled/forced, and known Supabase default grants (including TRUNCATE) are revoked on these tables. A superuser/BYPASSRLS web role is rejected. Other deals grants are unchanged. If the role does not exist, it is created NOLOGIN; configure its login/authentication yourself without committing credentials. Never give it service-role membership.
2. Review the committed `earnings/publication/published_snapshot_seed.sql` and run it as administrator. It contains only the existing eight published prediction copies and the clearly labelled backtest summary. It is repeatable and cannot read/write any live table. Published copies can be replaced by the owner; the underlying live ledger remains immutable. `published_at` uses the database clock, while source `copied_at`/backtest execution times remain their actual original values.
3. Configure server-only `CROSSCHECK_PUBLISHED_DATABASE_URL` for the `dealtrace_web` connection. Do not put the URL in source code or a public environment variable. Missing configuration, an unexpected role, unavailable tables, or malformed payloads fail closed. No credential is created or printed by the scripts.
4. In `apps/web`, run `npm ci`, `npm test`, `npm run build -- --webpack`, then `npm run start`. Webpack is the supported fallback used here because Turbopack's local worker-port binding was blocked in this environment. Main's Inter/Fraunces fonts require Google Fonts during build. The page reuses main's Card, HeroMedia, typography and design tokens; CSS changes are scoped to the predictions module.

After a separately approved scoring operation, refresh the existing publication export, review it, run `.venv/bin/python -m earnings.publication.snapshot_sql`, and manually apply the new seed SQL. The generator reads publication JSON only and never connects to a database. It does not authorize scoring or publication by itself. Backtest results come from `.venv/bin/python -m earnings.backtest_walkforward`; they never become live prediction inputs.

Verification used an isolated temporary PostgreSQL cluster, not Supabase or the live database. Both DDL and seed were repeatable; the web role could SELECT the copies and could not INSERT/UPDATE/DELETE/TRUNCATE or read a private sentinel table. An unrelated role with SELECT saw zero rows under RLS. Administrators can alter tables, policies or published copies; this does not claim administrator-proof integrity. Visual browser compatibility is unverified: no browser automation was used. HTTP verification confirmed eight cards/method records, the backtest, navigation, scoped classes, background poster markup and successful stylesheet assets.
